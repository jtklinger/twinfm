## Gotchas hit this session

- **Console checks after the triplet, never before.** A recursive search of `C:\` before the
  P3-M2 gate left Defender busy and lifted the whole machine five points for the run; the
  P3-M3 and P3-M4 sessions, with checks after, were the quietest yet (every run within one
  point). The protocol note is in the P3-M2 record and in memory.
- **Gate runs come as ONE command** (`tools/wpr-triplet.ps1`): Jeremy asked for it after six
  separate commands caused a false start. Confirm the candidate binary's build has finished
  (the `ls` timestamp) before handing the command over; a run that starts before the exe exists
  leaves a WPR session open until `wpr -cancel`.
- **A running TwinFM locks its exe**: a gate rebuild into `target-<name>` fails with "Access is
  denied" while Jeremy's console window from that build is open. Ask him to close it first.
- **Jeremy's stderr capture** for a console-only check: `twinfm.exe 2> C:\traces\<name>.stderr.txt`
  from an unelevated PowerShell; the file is UTF-16 (`iconv -f UTF-16LE -t UTF-8`). Say exactly
  which window to drag from: "open the zip in Explorer and drag an entry from inside it" was
  first read as "drag any file", and the first capture proved nothing.
- **Any per-row binding or conditional on a runtime property costs a measurable fraction of a
  point on 40k rows** (P3-M1: 1.5 for an `if`, 0.7 for two bindings). Choose row structure
  outside the `for`; prove with the generated code diff against the reference's row.
- **Slint snaps a rebuilt ListView to a whole row** when it is created already scrolled (the
  random-seek branch of `ensure_updated_listview` drops the fraction); it also happens on tab
  switches and thumb drags today. P3-M5's view switch will rebuild the list: expect it.
- **The shell's zip folder crashes in `QueryInterface` for IContextMenu2/3** (access violation);
  P3-M4 skips that routing inside archives. Its `IFileOperation` rename, delete, move-out and
  new-folder hang for 15 s or more; they are refused before any shell call.
- **Explorer's zip view drag offers `FileGroupDescriptorW` + `FileContents` (ISTREAM) + a Shell
  IDList Array with async capability**; `SHCreateDataObject` over zip items offers the IDList
  only. The drop target reads both. A "refused" diagnostic must key on the OFFER, not on the
  spot under the pointer (a drag entering over no target logged a false refusal once).
- **Heredoc Python with Windows paths**: `"C:\Users"` and `"\W"` in a normal string are escapes
  (a `\a` became a BEL byte in the plan doc and needed a fix-up commit). Use raw strings or
  write the text through the Write tool.
- **`gh pr merge` can report "not mergeable"** for about a minute after a push while GitHub
  recomputes; wait and retry; `UNSTABLE` with CI pending still merges (no branch protection).
- **The implementer's checks leave traces on the desktop**: 75 scratch folders in the Recycle
  Bin and an overwritten clipboard from P3-M4's extraction checks. Warn Jeremy when a brief
  includes real shell operations.
